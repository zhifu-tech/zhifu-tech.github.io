本文档提供 Kotlin Multiplatform Default Hierarchy Template 的完整概念模型，包含所有 targets 的压缩但完整默认层次结构总览图（含 webMain），严格对齐官方概念层次。

🧠 Kotlin Multiplatform 默认层次结构（Mermaid）

🔑 如何"读"这张 Mermaid 图（快速对齐官方语义）

核心概念

  • 箭头方向 = dependsOn

    • 下层 source set dependsOn 上层
    • 例如：jsMain dependsOn webMain，webMain dependsOn commonMain

  • 最底层节点 = targets 对应的 xxxMain

    • 这些是你在 build.gradle.kts 中配置的 target 对应的 source set
    • 例如：js(IR) → jsMain，linuxX64() → linuxX64Main

  • 中间层（webMain / nativeMain / appleMain / linuxMain …）

    • 由 Default Hierarchy Template 自动生成
    • 用于代码共享和层次化组织

  • macosMain 双父节点

    • 同时来自 nativeMain 和 appleMain（官方设计）
    • 体现了 macOS 的双重身份：既是 Native 平台，也是 Apple 平台

层次结构说明

  1. commonMain：所有平台的公共代码
  2. 平台分组：
    • Web 组：webMain → jsMain / wasmMain
    • JVM 组：jvmMain / androidMain
    • Native 组：nativeMain → 各平台特定 source set
  3. Native 子分组：
    • Linux：linuxMain → linuxX64Main / linuxArm64Main
    • Windows：windowsMain → mingwX64Main / mingwX86Main
    • Apple：appleMain → macosMain / iosMain / watchosMain / tvosMain

💡 核心要点

  1. 层次结构是自动生成的

    • 当你配置 targets 时，Kotlin Gradle Plugin 会自动创建中间层 source set
    • 无需手动创建 webMain、nativeMain 等中间层

  2. 代码共享策略

    • 放在 commonMain 的代码会被所有平台共享
    • 放在 webMain 的代码会被 jsMain 和 wasmMain 共享
    • 放在 nativeMain 的代码会被所有 Native 平台共享

  3. macOS 的特殊性

    • macosMain 同时继承自 nativeMain 和 appleMain
    • 这意味着 macOS 代码可以：
      • 使用 Native 平台的通用代码（来自 nativeMain）
      • 使用 Apple 平台的通用代码（来自 appleMain）

  4. 实际项目中的使用

    • 大多数情况下，你只需要关注：
      • commonMain：所有平台共享
      • 平台特定的 xxxMain：如 jsMain、androidMain、iosArm64Main
    • 中间层（如 webMain、nativeMain）主要用于：
      • 多个相关平台之间的代码共享
      • 减少重复代码

✅ 一句话总结

这份 Mermaid 图就是"全 target 启用时，Kotlin 官方默认层次结构的压缩概念模型"，可直接用于文档、分享或团队共识。
